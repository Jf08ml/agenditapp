## Architecture

**Next.js 15 (App Router) marketing site** for AgenditApp, a LATAM (Colombia-first) scheduling SaaS. Public-facing only — the actual product lives at `app.agenditapp.com` (`SIGNUP_HREF`). Code comments and content are mostly in Spanish.

### i18n (next-intl) — the most important thing to understand

All pages live under `src/app/[locale]/`. Config is in `src/i18n/routing.ts`:

- Locales: `es-419` (default, **never appears in URLs**) and `en` (prefixed `/en/...`), `localePrefix: "as-needed"`, no locale detection.
- The default is `es-419`, not `es`, on purpose: `/es` is a real route (Spain country page) and would collide.
- Only the routes listed in `pathnames` have an English version, some with translated slugs (`/precios` → `/en/pricing`, `/funcionalidades` → `/en/features`, `/sectores` → `/en/industries`, `/terminos` → `/en/terms`, `/privacidad` → `/en/privacy`, plus `/` and `/blog`). Use `Link`/`getPathname` from `src/i18n/navigation.ts` for these.
- **Every Spanish-only page** (sector pages, country pages, `vs/*`, `ref/*`, `oferta*`, `presentacion`, `nosotros`, `seguridad`…) must export:
  ```ts
  export function generateStaticParams() { return [{ locale: routing.defaultLocale }]; }
  export const dynamicParams = false;
  ```
  so `/en/...` versions 404 instead of rendering Spanish. When translating a page, remove this, add it to `pathnames`, and add it to the English section of `sitemap.ts`.
- Messages: one JSON file per namespace in `src/messages/{es-419,en}/`, aggregated by `index.ts` barrels. To add a namespace, create the JSON in **both** locales and add it to both `index.ts` files (they say they're generated by `build-barrels.js`, but that script is not in the repo, so edit them by hand in the same alphabetical style).
- Translated pages use `getTranslations` in `generateMetadata` and set `alternates.languages: withEnglish("/en/...")` (`src/lib/hreflang.ts`). Spanish-only pages use `HREFLANG_ALTERNATES` (country variants only) — never advertise an `en` alternate that doesn't exist. OG locales come from `ogLocale` / `ogAlternateLocale`.
- `<html lang>` renders `es-CO` for the default locale (`src/app/[locale]/layout.tsx`).

### Middleware (`src/middleware.ts`)

Wraps the next-intl middleware with a geo-block: requests from `BLOCKED_COUNTRIES` (via `x-vercel-ip-country`) get rewritten to `/no-disponible` with status 451. Search/social/AI crawlers (`BOT_USER_AGENT_PATTERN`) bypass the geo-block but still go through next-intl. The matcher excludes `api`, `_next`, `_vercel`, `og` and files with extensions.

### Code layout

- `src/app/(landing)/sections/` — homepage sections, composed in `src/app/[locale]/page.tsx` (check there for current order). `Hero` includes the navbar.
- `src/app/(landing)/components/ui/` — shared UI (`PageHeader`, `PageFooter`, `SectorPageContent`, `DemoCtaModal`, `PromoPopup`, `WhatsAppFAB`…). Standalone pages use `PageHeader` + `PageFooter`. Sector pages pass static Spanish data (features, FAQs, schemas) to `SectorPageContent`.
- `src/app/(landing)/components/lp/` — paid-campaign landings (`/oferta`, `/oferta-registro`, `/presentacion`), which are `noindex`.
- `src/app/(landing)/components/constants.ts` — WhatsApp/signup links and locale-aware JSON-LD builders (`getJsonldOrganization(locale)` etc.), rendered via `seo/SchemaOrg.tsx`.
- Country pages: `src/app/[locale]/{mx,cl,ar,es,cr,ec}/page.tsx` (Colombia is the root).
- `vs/[competitor]` and `ref/[slug]` hold their data inline (`competitors` object; `ref/sources.ts` / `influencers.ts` for referral partners).
- `src/app/sitemap.ts` is **mostly hand-maintained** — new static pages must be added manually. Blog posts are added automatically.
- `src/app/og/route.tsx` generates OG images from `?title=&subtitle=&tag=` query params.

### Blog

MDX files read by `src/lib/blog.ts` (gray-matter, every function takes a `locale`) and rendered with `next-mdx-remote` + `remark-gfm`. Adding a file is enough: it shows up in the listing and the sitemap. Frontmatter and MDX components (`<CtaBox>`, `<TipBox>`, `<CheckItem>`, `<Compare*>`) are documented in README.md; category badge colors are in `CATEGORY_COLORS` in `src/app/[locale]/blog/BlogList.tsx`.

- Spanish posts: `src/content/blog/*.mdx` (filename = slug).
- English translations: `src/content/blog/en/*.mdx` with a **translated slug** and `translationOf: "<spanish-slug>"` in frontmatter. `getPostTranslations` uses that to emit `hreflang` (es/en/x-default) only when both versions exist. Untranslated posts 404 under `/en/blog/*` (`generateStaticParams` only emits slugs that exist per locale). Categories are translated too (`Business Management`, `Comparisons`, `WhatsApp & Communication`, `Practical Guides`).
- Post page UI strings live in the `BlogPage.post.*` messages; `<Compare*>` table data per locale is in `src/app/[locale]/blog/[slug]/compareTables.ts`.
- English posts should link to `/en/blog/...`, `/en/pricing`, `/en/features`, `/en/industries` — sector and `vs/*` pages are Spanish-only.
- When writing posts, only claim features that appear in `src/messages/es-419/Funcionalidades.json` / `Precio.json` (plans: Gratuito $0; Básico $12 — 1 professional, WhatsApp confirmation + 1 reminder for up to 50 appointments/month; Esencial $20 — unlimited professionals and WhatsApp with no cap; Marca Propia $30).

### Backend / integrations

- `POST /api/leads` — saves to Firestore `leads` collection (`src/lib/firebaseAdmin.ts`) and notifies by email via `MAILER_URL` → `LEADS_NOTIFY_EMAIL`.
- `POST /api/capi` — Meta Conversions API relay. `components/metaTracking.ts` fires each campaign CTA event both from the browser Pixel and through `/api/capi` with the same `event_id` so Meta can deduplicate them. Only used on `/oferta*` landings; `source` → `content_name` mappings live in `metaTracking.ts`.
- Analytics: Vercel Analytics + GA4 (`G-ERKL5G7HS8`) in the locale layout; Google Ads conversion fired from `DemoLead.tsx` via `window.gtag`.
- `next.config.ts`: www→apex redirect, security/cache headers, `ik.imagekit.io` allowed for `next/image`.

### Styling

- Tailwind v4 via PostCSS. Design tokens are CSS variables in `src/app/globals.css`, exposed through `@theme inline`: `bg-brand` (#1D4ED8), `bg-brand-hover`, `bg-bg-main`, `bg-bg-card`, `text-heading`, `text-body`, `text-muted`, `success`, `danger`, `shadow-card`, and `--radius-sm/md/lg` (10/12/14px). Utility classes: `.btn-primary` and `.card`. The full design guide is in README.md.
- Fonts: Poppins 400/500/600 (`--font-poppins`) plus Instrument Serif italic (`--font-instrument-serif`) for accents. **Never use Poppins 300 or 900.**
- Framer Motion animations: `whileInView` + `viewport={{ once: true }}` with `fadeIn`/`fadeInUp`/`cardIn` variants. Components using motion, state or `useTranslations` hooks are `"use client"`.
